# 《这一身》配音管线机 v1

定位：`声音系统设计-v1.md` 管**设计正典**（四层声音、表演规则、触发合同）；本文管**生产管线**——一个新声音从需求到进包的完整流水线，对标美术的生图管线机。

## 一、声源三级分类（每个新声音先过这一关）

| 级别 | 判定 | 管线 | 例子 |
|---|---|---|---|
| **S 素材级** | 现实中存在的、不含台词的声音 | freesound CC0（Openverse 检索 → sha256 锁定 → `fetch_curated_sound_assets.mjs` 的 `sources` 表 → `sound-manifest.json` 记 license） | 上课铃、电话忙音/铃声、叫号叮咚、门禁滴声、列车进站、拍桌子 |
| **A 设计级** | 有台词的**关键角色**，303 个系统预置里没有合适的 | MiniMax voice_design：`node scripts/design_voice.mjs --id=<slug> --prompt=<音色描述> --preview=<正典台词>`，voice_id 持久化，选定后写进 `.env.local` 或选角表 | 旁白、父亲（已有）；领导（候选已设计） |
| **B 预置级** | 有台词的普通 NPC | 303 个系统音色里选角，登记在 `generate_minimax_voice_assets.mjs` 的 `systemVoiceByRole` | 老师、护士、广播、邻居 |

判定顺序：先问"这声音现实里买得到吗"（S），再问"这个角色重要到值得专属声线吗"（A），否则 B。

## 二、五段流水线

```
契约 → 选角 → 生成 → QA → 审听
```

1. **契约**：台词、触发、语速/音高/情绪/停顿全部写进 `src/voice-script.ts`（每句显式 delivery，禁止全局默认）。**台词文本是正典，走隐喻字幕定稿流程：先列意图 → 用户纠偏 → A/B 候选 → 用户挑。**
2. **选角**：
   - 试音：`node scripts/generate_voice_auditions.mjs` → `tmp/voice-auditions/index.html`（每个角色 2–3 个候选 × 真实台词 × 契约参数，用耳朵挑）；
   - 设计：`node scripts/design_voice.mjs`（A 级角色，见上表）；
   - 定稿写入 `systemVoiceByRole` / 环境变量。**任何两个具名角色不得共用音色**（机构声——广播/门禁/银行热线——统一新闻女声是有意例外）。
3. **生成**：`npm run generate:voice`（全量）或 `--only=id1,id2 --force`（单条重做）。内置 RPM 限流退避重试。模型 `speech-2.8-hd`（离线批量生产要表现力不要速度，**不用 turbo**）。
4. **QA**：`npm run audit:voice` —— Whisper 反向转写出 `qa-report.json`。同音字（工牌/公牌）、@ 读"艾特"、呼吸标签被听成"啊"都是**误报**；真正要抓的是漏字、错音、过慢。
5. **审听**：`/voice-review.html`（dev 审听台，逐条核对合同）→ 真机 WebView 听感 → `npm run validate:voice:strict` 门禁 → 进包。

## 四、纪律

- 运行时零 TTS：一切语音预生成、人工试听、随包发布（`声音系统设计-v1.md` 固定资产边界）。
- 生成脚本对 `rate limit` 自动退避重试（15s 递增，5 次上限），批量任务不需要人工分批。
- 新增角色必须先过三级分类，再走五段流水线，不允许跳过试音直接定角。
- 台词文本改动=正典改动，必须经用户；音色/参数改动可先试音后汇报。
- S 级素材必须 CC0/明确授权，`sound-manifest.json` 记录来源与 sha256，禁止无 license 素材进包。
