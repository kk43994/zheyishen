# 《这一身》主角道具外观系统 v2

> 状态：完整设计提案，等待视觉方向确认；不得直接替换运行时资源。

主角母版必须先通过 `docs/主角母版优化方案-v2.md`。母版静态四视图未确认前，本文的 74 件资源只做设计，不进入批量生图与运行时替换。

## 1. 目标

玩家拿到任何一件道具后，都必须在主角身上看到它留下的后果，但不是把 74 件物品同时挂成一棵圣诞树。每件道具有三层反馈：

1. **拾取变身**：获得道具时，用 0.7–1.1 秒展示物件贴上身体、身体发生变化、机制符号出现。
2. **构筑签名**：战斗中保留一个稳定、远看可辨的外观特征。
3. **机制触发**：效果真正生效时，再出现该道具独有的动作、弹体、影子或特效。

只改变一两个难以察觉的像素、只换衣服颜色、只画一个通用光环，均不算完成。

## 2. 视觉载体

每件道具从以下五类载体中选一个主载体，最多再选两个副载体：

| 载体 | 用途 | 生产方式 |
| --- | --- | --- |
| 刚性物件 `R` | 眼镜、钥匙、手机、背包、卡册等不会随身体弯曲的物件 | Image2 提造型，程序按四方向锚点挂载 |
| 服装覆盖 `G` | 雨衣、校服、领带等必须随动作变形的整片衣物 | Image2 概念 + 人工像素化分层，按动作图集生产 |
| 身体变化 `M` | 高矮胖瘦、驼背、黑眼圈、白发、表情与局部色变 | 代码执行整数像素形变与遮罩 |
| 触发特效 `V` | 雪花、时间停滞、已读挂账、闪现、护盾、声浪等 | 小型像素帧 + 代码路径/时序 |
| 弹体签名 `P` | 分裂、折返、追踪、雾化、弹跳、回声等构筑结果 | 单弹体合成器按 flags 程序绘制 |

## 3. 固定骨架与锚点

主角继续使用 `40×56` 逻辑画布和 `(20,49)` 脚底锚点。身高、胖瘦和姿态只做整数像素分段形变，不生成不同体型的完整道具套装。

锚点固定为：`head`、`face`、`neck`、`chest`、`back`、`leftHand`、`rightHand`、`waist`、`feet`、`shadow`。所有锚点必须有前、后、左、右四向位置，并继承待机、走路、攻击、受伤的动作偏移。

渲染层从后到前为：地面影子 → 远景光环 → 背部长物 → 身体 → 服装 → 后手物件 → 胸腰附件 → 头脸 → 前手物件 → 前景触发特效。左右朝向时，前手和后手交换；背面时，脸部附件隐藏，背部附件移到身体前层。

## 4. 同时穿戴与冲突规则

身体形变全部累计，但有上限：横向最多增减 3 像素，纵向最多增减 3 像素，弯腰最多 4 像素。`断掉的脊梁骨`拥有最高姿态优先级，其次是`装满石头的书包`，其他疲惫类效果只增加肩膀和头部偏移。

常驻构筑签名最多显示六个：1 个体型/姿态、1 件主服装、1 个背部物、1 个头脸物、1 个手持或腰挂物、1 个影子/光环。发生冲突时按“正在触发 > 组合核心 > 品质 > 最近获得”决定主显示；被压下去的道具仍在拾取动画和触发动画中出现。

同类物件不互相覆盖，而是升级成组合造型。例如两把钥匙合成一串钥匙；多份合同变成缠住手臂的纸带；多个手机类道具共用一台屏幕，但通知灯、裂纹和回声各自保留。

## 6. 体型与身体后果

体型不是独立皮肤，而是所有道具共同算出的 `BodyMorphState`：

- 出生固定为标准身高、标准体型；AI 只决定脸、发型、肤色、姿态和基础衣服。12 种体型组合只用于道具结果与资源压力测试。

- 变瘦来源：药物透支、熬夜、烟、时间预支、麻木等；最多收窄 3 像素。
- 变胖/变软来源：深夜外卖、母亲的饭、将就吃完、枕套躺平等；最多加宽 3 像素。
- 驼背来源：石头书包、断脊梁、合同和长期疲惫；断脊梁覆盖其他姿态但仍累计肩降。
- 年龄来源：提前花掉的十年、关服、女儿乳牙等只增加灰发、眼袋和动作迟滞，不直接换一张老人皮肤。
- 狂暴与崩落属于临时形变，结束后回到累计状态。

所有刚性物件先绑定逻辑锚点，再经过同一形变矩阵；服装覆盖层使用头、肩、腰、脚四段九宫格变形，禁止对完整 PNG 任意缩放。

### 6.1 现有工程诊断

现有工程已经具备可保留的底盘：`40×56` 固定骨架、12 种整数像素体型、四方向动作、十个动作锚点、前后渲染 pass、刚性槽位和 74 件穷尽式登记。问题不在“有没有配置”，而在“配置有没有真正画出来”：

- 42 个调色 mutation 中，通用渲染基本只处理眼睛，头发、衣服、皮肤、影子和轮廓大量失效；
- 14 个 silhouette mutation 中，基本只有头发轮廓有实际绘制，躯干、背部、外套和影子形变没有统一处理；
- 16 个 posture mutation 大多没有改变骨架，只剩少量肩降像素和个别硬编码特判；
- 52 件道具声明了动画，但独立周期、低血、章节开始和事件触发没有接入正式角色状态；
- 槽位冲突会把道具降级成脚边像素点，既不可读，也会被误认为网格噪点；
- 旧管线的部分清单仍停在 72 件，没有覆盖新加入的两件遗物。

因此 v2 先把每件道具编译成一个 `HeroAppearancePlan`：确定身体形变、实际槽位、前后层、遮挡、语义降级、静态贴图和动态事件。这个计划只在装备变化时重算；静态身体与穿戴层进入缓存，时间相关的 aura/event 单独绘制，不能把每帧时间塞进静态角色缓存。

## 7. 管线机生产方案

### 7.1 输入

每个 Image2 任务必须上传三类真实参考图：

1. `output/art-style-reference-v1/canonical-style-board.png`；
2. 已通过的主角四视图与运行时动作图集；
3. 该批道具的现有图标或真实物件语义参考。

提示词只描述本项目的逻辑尺寸、轮廓、色板、光向、锚点和叙事用途，不写其他游戏名称。Image2 输出必须带固定注册网格、纯色键控底、足够留白、无文字、无阴影、无格间越界。

### 7.2 分批

1. **刚性物件批**：眼镜、钥匙、手机、手表、药板、相框、卡册、麦克风等，按四方向静态源生产。
2. **服装批**：雨衣、小号校服、领带、枕套，只先做四方向待机，通过后人工映射到全部动作。
3. **头脸批**：漂发、泪痕、黑眼圈、强笑、momo 面具、空白姓名贴等，以遮罩和少量附件为主。
4. **影子批**：老年影子、新生影子、电子宠物、电梯门缝、伤害重块等，使用独立影子图集。
5. **触发特效批**：每件 2–4 帧，只制作不可由几何图元表达的局部像素动画。

### 7.3 输出

- `hero-props-v2.png`：刚性附件四方向图集；每格仍是 `40×56`，透明底。
- `hero-garments-v2/<item>/<motion>.png`：需要随身体动作变形的服装覆盖。
- `hero-face-masks-v2.png`：头发、脸部痕迹、表情和面具遮罩。
- `hero-shadow-v2.png`：角色身后和地面上的独立剪影。
- `hero-item-vfx-v2.png`：统一尺寸的小型触发动画。
- `item-visual-manifest-v2.json`：锚点、层级、四向偏移、遮挡、帧率、优先级和组合规则。

刚性槽位满时必须进入预先设计的语义降级位，例如合同折进内袋、卡册只露书脊、钥匙并入钥匙串、手机共享一块屏幕。禁止降级成无意义的脚边亮点，也禁止彻底隐藏。

## 8. 后处理与自动验收

管线机生成结果永远只是候选源。后处理依次执行：固定网格裁切 → 去键控底 → 透明 RGB 清零 → 降到逻辑像素 → 限色 → 轮廓修复 → 锚点对齐 → 图集编排。

自动验收必须覆盖：

- 四方向不镜像偷懒，左右手、背包、信封、钥匙位置正确；
- 待机、走路、攻击、受伤全部不漂脚、不穿身体、不越过 `40×56`；
- 瘦、普通、胖、矮、平均、高的 12 种身体组合；
- 最拥挤的六签名组合仍能看见主角脸、脚和攻击方向；
- 1× 逻辑尺寸与移动端实机尺寸均可辨认；
- 获取动画、常驻签名和机制触发三种状态都有截图接触表；
- 任何资源在静止时不制造半透明网格、白边或高清缩图噪点。

## 9. 第一轮视觉门禁

全量生产前只做八件代表性样品：`父亲的雨衣`、`装满石头的书包`、`同桌的修眉刀`、`一直空着的相框`、`自动续费到明年的会员`、`母亲留在锅里的那碗饭`、`交掉的闪现`、`没有痛觉的夜晚`。它们分别验证外套、体积背件、手持与身体痕迹、背后框体、世界空间光环、体型与护盾、瞬时事件、动态影子与伤害重量。

八件必须先给出：四方向静态图、动作叠加接触表、瘦/普通/胖三体型接触表、八件同时穿戴的拥挤测试。用户确认后才按同类批量扩展到 74 件。

## 10. 实施顺序

1. 先完成 `HeroAppearancePlan`、统一锚点来源、全部 mutation/animation handler 和静态/动态分离缓存，不生图。
2. 把本文件 74 件映射转成机器可校验 manifest，要求每个 `ItemId` 至少有一个可执行的 persistent 或 event renderer。
3. 用八件门禁样品跑通管线机，并生成四向、全动作、三体型和拥挤接触表。
4. 用户确认后，按刚性物件、服装、头脸、影子、触发特效五批生产其余 66 件。
5. 最后接入拾取变身动画、机制触发动画和组合升级造型，并在移动端压力测试。
