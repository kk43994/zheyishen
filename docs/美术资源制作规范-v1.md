# 《这一身》美术资源制作规范 v1

> 状态：生产基线。所有新美术必须先过本规范和实机尺寸审阅，再进入 `src/assets`。

## 1. 核心视觉命题

《这一身》不是泛化的“暗黑像素风”，而是两套相互咬合的视觉系统：

1. **人生档案**：用于标题、出生档案、命运选择、道具档案、结算与百科。视觉词汇是旧纸、墨线、红印、登记号、裁切缺口和少量手写痕迹。它表达“一生被记录、被定义”。
2. **流动人生场**：用于持续战斗、关卡地表、敌人、弹道和即时反馈。视觉词汇是清楚的中间调、随年龄变化的日常光线、平铺地面、生活物件怪物化、明确轮廓和少量强调色。它表达“人在时间中不断向前”。

两套系统共享同一色板、轮廓色、顶左光源、逻辑像素密度和叙事物证，但不强求相同的细节量。

## 2. 正典参考优先级

发生冲突时，按以下顺序判定：

1. 已在游戏中稳定运行的图集与程序化角色。
2. 三张主流程截图：标题、出生档案、战斗。
3. `docs/UI设计规范-v1.md` 与 `docs/这一身百科.html`。
4. 经用户通过的主角四视图与动作帧。
5. Image2 概念图。概念图不得反向覆盖前四项。

统一参考板由 `scripts/build_art_style_reference.py` 生成：

- `output/art-style-reference-v1/canonical-style-board.png`

## 3. 共享色板

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| 深墨 | `#111116` | 最深轮廓、危险边缘与终局夜色；禁止铺满前五章战场 |
| 暗面 | `#1B1A20` | 物件背光面与档案深层，不作为日常地表主色 |
| 墨色 | `#17151A` | 纸面文字和像素轮廓 |
| 软墨 | `#3E3A3D` | 次级线条与暗部 |
| 旧纸 | `#D8D0C1` | 档案主底 |
| 亮纸 | `#E8E1D3` | 呼吸、高光和少量纸面磨损 |
| 暗纸 | `#AAA297` | 次级信息 |
| 纸影 | `#786F69` | 纸面阴影和旧化 |
| 旧红 | `#9F3548` | 红印、伤害、危险中心 |
| 暗红 | `#642231` | 旧红阴影 |
| 雨衣黄 | `#C6A44A` | 记忆、庇护与稀有亮点 |
| 雨衣暗黄 | `#75622F` | 雨衣黄阴影 |
| 医院蓝灰 | `#71818A` | 冷感场景和金属 |
| 深蓝灰 | `#38434A` | 冷感暗部 |

每个新生产资源优先从上述核心色阶取 70% 以上的可见颜色；同一家族允许在相邻明度和色相内建立自己的材质色阶。既有运行时资源以视觉色差接近为合格，不为了命中十六进制数值做破坏材质的机械换色。一个界面同时只允许一类高饱和强调色。

UI 品质层级不得另建紫、橙、彩虹等“稀有度色系”。Ⅰ至Ⅳ级固定使用医院蓝灰、纸影、旧红、雨衣黄；差异同时依靠罗马数字、框线复杂度和明度表达，关闭颜色后仍须可辨。

以下不按“精确命中色值”机械验收，但仍受轮廓、光向和像素密度约束：

- 仅供代码重新着色的白色遮罩，不属于最终可见颜色；
- 冰冻、电弧、治疗等必须一眼识别的功能特效，可使用蓝白、青色等语义色；
- 旧照片、污迹和磨损允许在相邻明度内偏移，但不能形成新的主色系。

风格统一的优先级是：轮廓与像素语法 > 光向与明度层级 > 核心色阶关系 > 局部语义强调色 > 精确色值。统一不等于把所有资源染成同一种颜色；禁止用逐像素最近色粗暴重映射已经通过的角色与敌人。

## 4. 像素语法

- 所有运行时精灵先在逻辑尺寸上成立，再用最近邻缩放。
- 不得有抗锯齿、半透明发丝、柔焦、高清插画缩小痕迹。
- 主轮廓为 1 逻辑像素，使用深墨或墨色；内部线弱于外轮廓。
- 光源默认来自左上，暗部落在右下；同一图集不可更换光向。
- 主角建议 8–12 色，敌人 10–16 色，道具/摆设 12–20 色，12–20 px 的微型 UI 图标最多 2–4 个内部色。
- 精灵透明区的 RGB 必须清零，避免缩放时出现白边或绿边。
- 所有字体与长文案由程序渲染，不得烘焙进图片。

## 5. 资源槽位规格

| 类别 | 逻辑尺寸 | 图集/帧规则 | 锚点 | Image2 权限 |
| --- | --- | --- | --- | --- |
| 主角 | `40×56` | 前/后/左/右；待机 2、走路 4、攻击 2、受伤 2；12 种身高与体型组合 | `(20,49)` | **仅概念**；最终由现有图集和程序化整数像素叠加 |
| 主角外观变化 | 依附 `40×56` | 马可、面部、背部、手持、身体变形分层；四向与全动作必须完整 | 与主角共用 | **仅概念**；禁止完整头像或整件正面衣服直接接入 |
| 敌人 | `32×32` | `128×160`，4 列 × 5 行；待机 2、移动 4、攻击 2、受伤 2、消散 4；水平翻转面向 | 底部居中 | **概念 + 动作基础**；必须后处理到标准图集 |
| 道具 | `36×36` | `288×360`，8 列 × 10 行，当前 74 个 | 中心 | **可作基础图**；必须统一缩放、轮廓和色数 |
| 普通场景摆设 | `40×44` | 4 变体 × 6 人生阶段 | 底部居中 | **可作基础图**；不可各自使用不同透视 |
| 房间实体 | `64×72` | 门、摊位、灯等同行图集 | 底部居中 | **可作基础图** |
| 章节地面 | `128×128` | 无限平铺，6 个人生阶段，15–20 秒渐变换代；主体明度必须能在手机低亮度下辨认 | 无 | **只可生成平铺材质源**；禁止固定透视战斗背景 |
| 弹体 | `28×28` | 6 列 × 2 行 | 中心 | **可作基础图**；实机尺寸必须清晰 |
| 命中特效 | `32×32` | 4 列 × 4 行 | 中心 | **可作基础图** |
| 挽救特效 | `40×40` | 4 列 × 3 行 | 中心 | **可作基础图** |
| 羁绊特效 | `26×26` | 4 列 × 1 行 | 中心 | **可作基础图** |
| 状态图标 | `12×12` | 4 列 × 1 行 | 中心 | **只允许极简符号** |
| 章节转场/特殊房/结局 | `360×640` | 单幅插画，可配置程序化雨、闪灯、纸屑或呼吸动画 | 全屏 | **可作最终图**；不可冒充持续战斗地面 |

章节地面与摆设必须分层生产：地面只画可无限重复的材质与微小生活痕迹，不烘焙家具、强光、阴影或固定透视；摆设按小件 `0.74–0.90×`、中件 `0.96–1.18×`、大件 `1.30–1.45×` 三档在运行时缩放。大件只能成为场景簇的锚点，中小件围绕其形成床边、课桌、候车、饭桌、工位或病房组合；禁止所有物品以相同尺寸、相同密度均匀撒在地图上。章节换代时旧物先褪成地面浅痕，新物从脚底锚点按像素行向上显形并错峰落稳，不允许整张地图同时弹出。

## 6. 主角的特殊限制

主角是整个构筑系统的容器，必须保持固定像素骨架。高矮胖瘦使用以下方式：

- 固定 `40×56` 外框与 `(20,49)` 脚底锚点。
- 体型只做整数像素的横向增减和纵向分段拉伸，不做任意比例缩放。
- 道具外观分为头部、面部、躯干、背部、手持、足部、光环七类锚点层。
- 每件外观道具必须说明遮挡顺序、四向资源和在待机/走路/攻击/受伤中的偏移。
- 年龄、疲惫、瘦弱、臃肿等长期变化由代码统一执行，不为每个道具生成一套完整人物。

## 7. Image2 生产规则

1. 一次只处理一个资源家族，不混生主角、UI、敌人和背景。
2. 必须使用 Image2 `edit` 并实际上传参考图。`generate-batch` 只发送文字，不能作为风格统一依据。
3. 第一张参考图必须是 `output/art-style-reference-v1/canonical-style-board.png`，第二张必须是该资源家族的运行时图集，第三张才是语义或物件参考。`scripts/run_image2_reference_batch.py` 已将前两项设为硬门禁：缺少正典板、顺序错误或只有单张参考图都会直接终止任务。
4. 提示词不使用其他游戏名称作为风格捷径，只写本项目的色板、像素尺寸、轮廓、光向、锚点和叙事功能。
5. 模型输出是候选源，不是产品资源。后处理必须负责去背景、保锚点、限色、尺寸量化、透明 RGB 清零和图集编排。

## 8. 三道验收门

### A. 结构门

- 尺寸、帧数、排布、锚点和透明度完全符合槽位。
- 无越界、裁手、裁脚、白边、网格边或背景残留。
- 图集各帧脚底基线稳定，动画不漂移。

### B. 风格门

- 与统一参考板并排时，色相、色数、轮廓、光向和逻辑像素密度一致。
- 不得出现高清动漫脸、电影式完整透视战斗背景、光滑矢量图标或细碎油画笔触。
- 物件的隐喻来自造型和使用痕迹，不依赖烘焙文字解释。

### C. 实机门

- 必须在 1× 逻辑尺寸和实际战斗画面中检查，不能只看 6× 联络表。
- 主角、敌人、弹道和预警的层级必须在 300 ms 内可辨认。
- 新资源不能抢走战斗主体对比度，不得造成移动端文字或控件遮挡。
