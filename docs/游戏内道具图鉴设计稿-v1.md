# 游戏内道具图鉴设计稿 v1（讨论稿）

> 需求：把百科"接进"游戏 + 移动端适配，核心是道具图鉴。
> 硬约束：抖音互动空间离线 WebView（零 fetch、不能跳外链）→ 在线百科不可能被"链接进来"，只能**用包内已有数据在游戏里长出一个图鉴**。好消息：需要的资产全部已在包内。

## 一、定位与命名

- 在线百科（shen.kk666.best/wiki）＝**完整版**：Boss 逐帧、六章编排、彩蛋考据，给深度玩家和评委看（2026-07-29 起美术不再单列「美术馆」，各卷各带各的图，见 §29.26）；
- 游戏内图鉴＝**道具收藏册**：记录"这一身穿过什么"，驱动重开一局的收集欲。
- 命名建议：**《物证册》**（与游戏内"物证栏"同词根，比"图鉴"更贴黑色幽默语感；备选：《得到过的》《这一身·册》）。

## 二、零新增资产（8MB 红线安全）

| 需要 | 来源（已在包内） |
|---|---|
| 77 件图标 | icons.png + icons.json（item-icons.ts 已封装） |
| 名字/flavor/机制文案 | relics.ts（77 件全量） |
| 12 组合 + 奥义插画 | COMBO_DEFS + combo-art.png |
| 品质/房间归属 | relics.ts 字段 |
| 收录状态 | **zys-ledger-v1 名册**（最近 30 世每世 items）∪ 当前局 → "得到过"，零新存储 |

新增只有代码 + CSS，预计 <30KB。

## 三、信息架构

```
物证册
├─ 道具页（默认）: 5列网格 × 77格，按品质Ⅰ→Ⅴ分段
│   每格三种状态:
│   ① 未得到过 —— 暗色剪影 + 「？？？」（保留轮廓挠痒）
│   ② 得到过 —— 全彩图标
│   ③ 本局新收录 —— 全彩 + 红章「新」角标（结算页同步提示「本局收录 +3」）
│   点击格子 → 底部抽屉卡片: 图标大图 / 名字 / flavor / 机制一句话 / 来源房间 / 第几世第一次得到
├─ 组合页: 12 奥义，集齐的显示插画+组合名，未集齐显示灰色件数 (2/3)
└─ 册尾: 收录进度「63 / 77」+ 每档满收录盖一枚红章
```

- 「第几世第一次得到」直接查名册（"第七世，他第一次背起漏石头的书包"——用名册世数把收集变成人生记录，这是别的游戏图鉴没有的味）。
- **不做"见过未得"状态**（三选一里见过但没拿）：需要新增存储且意义弱，删繁。

## 四、入口与形态

- **入口**：标题页一枚「物证册」按钮（红章缝线样式）+ 结算页"本局收录 +N"点击直达。暂停菜单不放（战斗中不该翻册子）。
- **形态**：**DOM 全屏抽屉覆盖层**（不是 canvas 内绘制）。理由：77 格滚动列表 + 长文案排版，DOM 的滚动惯性/文字换行/触控点击全是免费的，canvas 手写这些是纯成本。视觉用 ui-theme.ts 的 UI_PALETTE 同源令牌 + 夜桌暗底 + 红章缝线母题，与 wiki v3 一个血统但独立实现（不引 wiki 的 css/js 文件，那套为桌面宽屏写的）。
- **移动端适配**：360 逻辑宽 5 列（64px 格 + 间距）刚好；卡片用底部抽屉（拇指区）不用悬浮 tooltip；顶部品质筛选 chips 可横滑；整册高度 100dvh、内部滚动，不动游戏 canvas。桌面端同一布局居中 420px 宽即可（游戏本来就是竖屏画框）。

## 五、与在线百科的关系

- 游戏内图鉴册尾放一行小字「完整档案：shen.kk666.best/wiki」（**纯文字不可点**——平台不许外链，文字提示不违规且评委能看见）；
- 在线百科反向不动（它已有物证墙）；
- 数据同源保证：图鉴直接读 relics.ts/COMBO_DEFS，与百科的 77 件校验同一正典，不会出现两边文案漂移——百科构建脚本已经从同一份数据生成。

## 六、实施切分（确认后动工）

1. **P1 骨架**：collection.ts（名册∪当前局→收录状态）+ 物证册 DOM 层 + 道具页网格与抽屉卡 + 标题页入口；
2. **P2 组合页与红章**：奥义插画、进度、满档红章、结算页「本局收录 +N」；
3. **P3 打磨**：新收录角标动效（红章盖下 0.3s）、翻页音效（page.wav 现成）、validate 门禁（77 格与 relics 数量断言）。
