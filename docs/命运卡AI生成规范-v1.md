# 《这一身》命运牌内容与生成规范 v1.0

> UI 正式名称是“命运牌”。文件名保留“命运卡”仅为兼容旧链接。

| 文档属性 | 值 |
|---|---|
| `policyVersion` | `fate-policy-1.0` |
| 适用范围 | AI 命运事件、咽吐回应、亲口回应、命运回响、本地保底事件 |
| 不适用范围 | 出生档案、普通道具文案、Boss 台词、结局文案 |
| 正典来源 | 本文；人生阶段以 `LIFE_STAGE_CANON` 为唯一时间线 |
| 规则词 | “必须/不得”是阻断规则；“应该”是质量规则；“可以”是允许项 |

模型、提示词或接口发生变化，不得改变本文定义的玩家体验与事实边界。模型测试、延迟和当前代码缺口记录在独立审计文档中。

“剧情残留 → 本地机制编译”与“后台生成、触发零等待”的架构已经落地，详见《命运牌剧情结算与后台生成设计 v1》。`effect/stats/hint/gainItemId` 仍是运行时和旧存档兼容字段，但 AI v2 不得输出；它们只由本地配方编译器产生。

## 1. 北极星

命运牌只回答两个问题：

1. **这一次，人生对他做了什么？**
2. **事情已经发生以后，他要怎样面对？**

核心体验：

> 发生什么，你说了不算。成为怎样的人，你还可以选。

> 这一生咽下去的东西，最后都变成了他吐出的那一口气。

一张好命运牌不是一段漂亮短篇，而是一次构筑选择。玩家应当先看懂一个已经成立的现实事实，再在两种都能理解、都带力量、也都留下代价的回应之间犹豫。

命运牌不得变成：

- 可以跳过、重掷或撤销事实的随机任务；
- “善良/邪恶”“勇敢/懦弱”的道德考试；
- 与本局年龄、穿戴物、记忆和构筑无关的通用鸡汤；
- 为追求反转而牺牲现实因果的微型小说；
- 让 AI 自由修改数值、代码或任意游戏状态的入口。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 命运事件 | 人生对主角做了什么；不可选择、不可刷新 |
| 事实底稿 | 只写时间、地点、人物、动作和直接结果的现实事件核心 |
| 事实落账 | 命运牌出现时先执行不可避免效果，并确认“已发生” |
| 命运轮廓 | `微光/交换/诱惑/反噬/荒诞/沉默` 六种事件预算 |
| 咽下 `swallow` | 让事实进入自己并改变自己；可能是接纳、适应、承担或压抑 |
| 吐出 `exhale` | 把回应送回外部；可能是询问、拒绝、表达、划界或伤害 |
| 五毒 | 贪、嗔、痴、慢、疑；记录回应背后的执念，不是善恶分 |
| 命运回响 | 选择后异步出现的 20–70 字页边字幕，只解释已执行的后果 |
| 命运回执 | 存档中的事件、所选回应和最终结果；重播时不得重新生成 |
| 人生记忆 | 程序从已审计事实与选择中派生的连续性记录 |
| 亲口回应 | 玩家自行输入的一句话；这句话被视为“他说了什么”，不自动成为现实 |
| 本地保底 | AI 失败后使用的人工事件；必须遵守与 AI 事件相同的规范 |

## 3. 玩家看到的成品

一张命运牌分四个时刻：

| 时刻 | 玩家看到什么 | 系统发生什么 |
|---|---|---|
| 预取 | 战斗中只显示“有件事正在发生” | 后台生成并校验，不打断战斗 |
| 事实落账 | 轮廓、标题、事实正文、“已发生” | 不可避免效果立即执行 |
| 咽吐选择 | 左侧咽下、右侧吐出；各有回应名和机械提示 | 玩家永久提交，不能跳过或重掷 |
| 回执与回响 | 先显示窄回执，随后回到战斗；回响异步出现在页边 | 记录五毒、构筑、记忆与命运回执 |

玩家理解事实后，应能在约两秒内读懂两个回应的区别。文本职责不得混用：

| 字段 | 玩家体验职责 | 文本预算 |
|---|---|---:|
| `title` | 给事件命名，不提前总结道理 | 2–16 字 |
| `fact` | 让玩家一次读懂已经发生什么 | 40–120 字，2–3 句 |
| `label` | 一眼看懂这边具体要做什么 | 2–14 字 |
| `hint` | 供程序和回执解释直接机械变化，不写第二段剧情；当前 UI 不直接展示原文 | 3–36 字 |
| `result` | 写选择当刻的动作与现场直接反应 | 12–90 字 |
| `memoryText` | 后续 AI 必须承认的事实摘要 | 程序派生，4–80 字 |
| 命运回响 `text` | 把已执行机制落回这一身 | 20–70 字 |

## 4. 人生时间线

`chapterIndex`、`age`、身份和场景必须服从同一张表：

| `chapterIndex` | 年龄 | 合法生活范围 | 禁止倒退或提前 |
|---:|---|---|---|
| 0 | 童年 | 未上学阶段；家里、照料者、柜子、床底、第一次害怕与承受 | 学校、同学、老师、工作、婚育 |
| 1 | 少年 | 小学至高中；课堂、排名、同伴目光、家庭与学校 | 正式工作、租房、婚育、退休 |
| 2 | 青年 | 毕业、求职、初入职场、租房、通勤、第一次独立生活 | 重新成为中学生、育儿、退休 |
| 3 | 成年 | 工作、伴侣、子女、照护父母、建立自己的家 | 重新成为学生、提前成为暮年身份 |
| 4 | 中年 | 职业压力、裁员风险、家庭责任、父母衰老、体检与账单 | 初次求职、实习生、中学生活 |
| 5 | 晚年 | 退休、疾病、照护、记忆与告别 | 在职青年/中年身份、学校生活 |

青年以后可以进入学校，但必须明确他是家长、工作人员或访客。旧校服、旧信和旧照片可以进入后来的人生，但必须说明保存位置、携带者和移动过程；旧物不能让人物回到过去。

若提示词、示例卡或本地事件与本表冲突，以本表为准。

## 5. 输入真相与字段所有权

一次生成只能相信冻结的 `LifeSnapshot` 和程序提供的预算。优先级如下：

1. 当前 `LifeSnapshot` 与人生时间线；
2. 已保存的命运回执和人生记忆；
3. 当前事件已经通过校验的事实底稿；
4. 提示词中的风格案例。

低优先级内容不得覆盖高优先级事实。道具名称可能是隐喻，不代表物理状态；只有道具摘要、已有记忆或事件正文明确写出的状态才成立。

预取快照只是生成依据，不自动保证展示时仍然有效。如果预取后生命、零钱、穿戴物、记忆、候选物品或人物状态发生了会改变事件因果的变化，展示前必须重新校验；无法证明仍有效时必须作废并重新生成或使用保底事件。

| 数据 | 所有者 | AI 权限 |
|---|---|---|
| 年龄、章节、生命、零钱、穿戴物、攻击、五毒、记忆 | 游戏程序 | 只读 |
| 命运轮廓、事实预算、回应预算、允许效果与候选物品 | 规则引擎 | 只能在白名单内选择和解释 |
| `id/title/scene/fact` | 事实生成阶段 | 生成一次，后续阶段只读 |
| `unavoidable/swallow/exhale` | 回应生成阶段 | 在预算内生成 |
| `memoryId/memoryText/source` | 游戏程序 | 不得生成或改写 |
| 文学化 `displayFact` | 文风阶段 | 只改句式和节奏，不改事实 |
| 最终数值与状态变更 | 游戏程序 | AI 只能返回白名单建议 |

`scene` 是校验上下文，不直接展示；玩家看到的是能够独立讲清事件的 `fact`。机械提示由程序根据 `effect/stats` 生成，不能依赖玩家看见模型返回的 `hint` 才能理解。

事件必须体现当前年龄和章节；原则上再自然引用一项本局穿戴物或记忆。接不自然可以不用，禁止为了显得“懂这一局”而硬塞旧物或强造因果。

## 6. 事实底稿合同

事实阶段只输出：

```json
{
  "id": "wrong_box_label",
  "title": "纸箱上的名字",
  "scene": {
    "time": "周五下午四点",
    "place": "公司人事会议室",
    "people": "他、人事、部门主管"
  },
  "fact": "周五下午四点，公司人事会议室里，人事把装着他工位用品的纸箱推到桌边，箱侧却贴着另一名同事的名字。他报出自己的工号，部门主管核对名单后把纸箱留在桌上，叫他先等。",
  "profile": "荒诞"
}
```

### 6.1 结构要求

- `id`：3–48 位英文、数字、下划线或连字符；本局内唯一。
- `scene.time`：2–18 字，必须具体；不得使用“某天”“后来”。
- `scene.place`：2–24 字，必须能判断人物所在位置。
- `scene.people`：2–28 字，必须包含“他”，且只能列人。
- `fact`：40–120 字、2–3 句；脱离 `scene` 也能读懂。
- `profile`：必须等于规则引擎本轮给定的命运轮廓。旧接口要求回传时只能原样回传。
- 不得输出选项、数值、道理、心理诊断或结局。

### 6.2 现实因果

事实必须自然写清：

1. 什么时候；
2. 在哪里；
3. 谁做了什么；
4. 动作造成了什么直接结果。

不得出现：

- 物体说话、认人、记事、做决定或无原因自行移动；
- 人物位置跳跃、动作缺少实施者；
- 路人无渠道知道私密信息；
- 公共设备展示陌生人的私密账号；
- 靠气味、划痕、照片缺口等普通线索完成认亲或破案；
- 为反转而安排的巧合、凭空证据或关键秘密；
- “他终于懂了”“生活就是”等替玩家总结的句子。

“荒诞”是现实制度和人的行为荒诞，不是现实因果失效。

### 6.3 六种命运轮廓

| 轮廓 | 内容职责 |
|---|---|
| 微光 | 小幅出口或被照顾的证据，不等于无代价奖励 |
| 交换 | 一项得到与一项失去价值相近 |
| 诱惑 | 立即强收益，留下长期代价 |
| 反噬 | 当前经历或穿戴物的负面回到主角身上 |
| 荒诞 | 数值可小，制度、身份或现场关系具有黑色幽默 |
| 沉默 | 事情可能没有解释或补偿，但必须留下事实 |

## 7. 咽下与吐出合同

回应阶段不得改写事实底稿，只输出：

```json
{
  "unavoidable": {
    "kind": "none",
    "amount": 0,
    "item": null
  },
  "swallow": {
    "label": "先认下纸箱",
    "poison": {
      "doubt": 1
    },
    "result": "他从此习惯把纸箱转到没有标签的一面再抱住；人事继续核对名单，部门主管没有再说话。",
    "residue": {
      "carrier": "habit",
      "motif": "guard",
      "intensity": "normal",
      "evidence": "从此习惯把纸箱转到没有标签的一面再抱住",
      "recipeId": "guarded_breath"
    }
  },
  "exhale": {
    "label": "让他们重新核对",
    "poison": {
      "pride": 1
    },
    "result": "他把纸箱推回桌中间，指着标签要求先核对；人事停下翻页，部门主管重新拿起名单。",
    "residue": {
      "carrier": "memory",
      "motif": "echo",
      "intensity": "normal",
      "evidence": "指着标签要求先核对",
      "recipeId": "memory_only"
    }
  }
}
```

### 7.1 不可避免效果

`unavoidable` 属于已经发生的事实，必须在玩家选择以前结算：

| `kind` | `amount` | `item` |
|---|---:|---|
| `none` | `0` | `null` |
| `damage` | 1–12 | `null` |
| `lose_coins` / `gain_coins` | 1–5 | `null` |
| `lose_max_hp` | 1–6 | `null` |
| `gain_item` | `0` | 只能是 `fateItemCandidates` 中未持有的合法物品 |

事实效果不能在没有预警的情况下直接终结一局。疾病、失业、离别等遭遇本身不得增加五毒；五毒来自主角如何回应。

### 7.2 方向定义

- 咽下是**回应向内**，不是“什么都不做”，也不是固定的软弱选项。
- 吐出是**回应向外**，不是固定的勇敢、正确或高收益选项。
- 两边必须从 `fact` 结束的同一时刻出发，并承认事实无法撤销。
- 咽吐与五毒不得固定绑定；一次咽下可以出于贪、痴或疑，一次吐出可以出于嗔、慢，也可以不增加毒。

每组选项必须同时通过四项测试：

1. **可执行**：主角在现场当刻确实做得到。
2. **可区分**：去掉“咽下/吐出”标题后，两种动作仍明显不同。
3. **可辩护**：两边都有普通人能理解的动机。
4. **有张力**：两边都有力量和代价，不存在明显全优答案。

禁止伪选择：两个选项只换语气、都做同一件事，或一边完整解决问题、另一边纯粹受罚。

### 7.3 回应的封闭世界

封闭世界主要约束回应与文学化，不约束事实阶段创造一件新的人生事件。

回应只允许使用：

- `fact` 已出现且仍在场的人、物和信息；
- `snapshot.items` 中明确穿戴在身上的物品；
- 主角自身的说、看、等、拿、放、问、拒绝等当场动作。

回应不得新增会改变因果或状态的：

- 关键人物、重新返回的离场人物；
- 可携带物、证件、药物、礼物、交通工具、证据；
- 新地点、工作任务、关系、秘密、伤病和人物往事；
- “后来”“当晚”“几天后”“聊了半夜”等长时间后续；
- 水渍、碰撞、来电、中奖等为了文采临时制造的新事件。

场景固有细节只有在输入的场景细节目录中出现，或完全不参与因果时才可用于留白。正式硬校验依赖结构化 `entityCatalog` 与状态字段；在这些字段接入前，不得宣称自然语言封闭世界已经可以由程序完全验证。

### 7.4 状态连续性

- 已扣款或已付款，不得再次付款。
- 已离场人物不得突然参与。
- 已丢失、烧毁、交出或不在现场的物品不得使用。
- `result` 只能写主角动作和现场人物的一次直接反应。
- 人物只能使用自己已经知道的信息。
- 一个选择不能靠新增事实替自己收尾。

### 7.5 剧情残留与机械字段

AI 回应只输出 `label/poison/result/residue`，不得输出 `hint/effect/stats/gainItemId`。`residue` 必须：

- 从本轮 `mechanicBudget.recipes` 逐字选择一个 `recipeId`；
- 使用该配方允许的 `carrier/motif/intensity`；
- 提供一段逐字存在于本回应 `result` 的 `evidence`；
- 没有具体物品、身体、习惯、穿戴物或资源残留时选择 `memory_only`；
- 不得因为勇敢、难过、尴尬、对白或文学隐喻获得战斗属性。

分支获得道具还必须同时满足：

- 事实底稿已把该候选道具放进现场；未出现于 `fact` 的道具配方不会下发；
- `candidateItemId` 来自本轮候选并与 `keep_item:` 配方一致；
- 实体物发生明确转交，非实体会员/账号记录发生明确开通、绑定、保存或记入账号；
- 只是看见、摸到、想起或比作该物品时不得获得。

`poison`：

- 只含 `greed/anger/delusion/pride/doubt`；
- 0–2 个键；
- 每项为 -1 至 2 的整数；
- 表示回应动机和构筑方向，不表示人格好坏。

程序根据 `recipeId` 生成最终 `hint/effect/stats/gainItemId`。模型即使夹带这些字段也不拥有数值权。已知普通配方若只是因果证据不足，安全降级为 `memory_only`；未知配方、伪造证据、候选外道具和事实中未出现的分支道具仍整项拒绝。

## 8. 文学化、记忆、回响与回执

### 8.1 文学化

当前生产链不再调用独立 `fate-style` 模型：事实底稿在本地格式与语义审稿通过后直接展示，避免多一次模型等待和事实漂移。以下合同保留为未来离线编辑器或非阻塞后处理的可选规范，不属于当前运行链。

文学化阶段只返回：

```json
{
  "displayFact": "..."
}
```

它只能调整句式、停顿和节奏。人物、物品、动作、对白、金额、时间、地点、原因与结果必须与事实底稿完全一致。若文学化版本改变一项事实，直接保留底稿。

### 8.2 人生记忆

`memoryId`、`memoryText` 和 `source` 由程序派生：

- `memoryId` 与事件 `id` 稳定对应；
- `memoryText` 只压缩正文已经明说的事实；
- 不得加入贫富身份、关系、秘密、原因或心理判断；
- 后续事件必须承认已保存记忆，已经失去的东西不能重新出现。

### 8.3 命运回响

命运回响只解释已经执行的回应和机械效果：

- 20–70 字；
- 优先点名一件穿戴物、已执行效果或主角外号；
- 不修改数值，不新增后果，不复述整件事；
- 写物不写理，允许克制留白，禁止格言和道德评判；
- 异步出现，不得阻塞玩家回到战斗。

### 8.4 命运回执

必须保存：

- 最终事实版本；
- 不可避免效果；
- 两个备选回应；
- 玩家实际选择或亲口回应；
- 最终结果文本；
- 本轮版本、来源和校验结果。

断点恢复与重播读取回执，不重新请求模型。

## 9. 亲口回应特殊合同

玩家输入最多 24 字。输入内容只代表“他把这句话说出口或尝试这样做”，不代表其中的主张成为现实。

例如玩家说“其实我是奥特曼”：

- 可以让现场人物要求他证明、把它当玩笑或终止谈话；
- 不可以让主角真的变身、获得超能力或召唤新角色；
- 不得拒绝玩家、说教或跳出游戏解释“我是 AI”。

玩家提交后先用原命运牌的本地配方同步结算“咽下/吐出”，AI 只异步补一段现场回响。自由输入失败、超时或玩家取消时，不阻塞战斗，也不覆盖已经提交的选择。

## 10. 文风与内容边界

《这一身》是黑暗童话，但两层必须分开：

- 世界、怪物、视觉和机制可以夸张、隐喻、梦境化；
- 命运事件的事实底稿必须遵守当代普通生活的现实因果。

写法遵循“先说人话，再留白”：

1. 第一眼读懂发生什么；
2. 第二眼看见一个具体当代物件或动作；
3. 最多在一个已经存在的现场细节上停半秒；
4. 不替玩家说出第三句。

黑色幽默讽刺制造、包装或消费困境的机制，不讽刺承受痛苦的人。不得：

- 把贫困、疾病、残障、肤色、外貌或家庭创伤写成人格报应；
- 对未成年人进行色情化描写；
- 详细描写自伤方法、极端暴力或可模仿的危险步骤；
- 用心理诊断代替人物行为；
- 用地域、职业、性别或弱势身份作低级笑点；
- 输出现实个人隐私、联系方式、账号或支付信息。

## 11. 生成与验收流水线

| 阶段 | 输入 | 唯一职责 | 阻断条件 |
|---|---|---|---|
| 0. 冻结快照 | 当前游戏状态 | 固定年龄、记忆、物品、预算和候选操作 | 快照自相矛盾 |
| 1. 事实生成 | 快照、轮廓、拒绝原因 | 只生成事实底稿 | Schema、年龄、现实因果不合格 |
| 2. 回应生成 | 已通过事实、回应预算 | 只生成不可避免效果、两个回应与剧情残留 | 新增关键实体、状态逆转、残留/配方非法 |
| 3. 语义审稿 | 快照、完整事件 | 找首个无法结构化的现实硬伤 | 未明确返回通过 |
| 4. 文学化 | 已通过事件 | 只改事实正文的句式和节奏 | 事实发生任何漂移 |
| 5. 最终复审 | 底稿、文学化稿 | 核对事实等价 | 未明确返回通过 |
| 6. 落账 | 最终事件 | 派生记忆、展示并执行事实 | 任一程序校验失败 |
| 7. 回应结算 | 玩家选择 | 本地编译并执行白名单配方、保存回执 | 证据、配方或冻结事件不一致 |
| 8. 命运回响 | 已执行回执 | 只写异步解释文本 | 新增事实或改写机制 |

模型语义审稿是另一项职责，不等于另一个独立模型，也不能覆盖程序校验结果。同一模型说 `valid=true` 不能证明它自己的输出正确。

生成失败时必须携带结构化拒绝原因定向重试。重试次数、超时和模型参数属于运行配置，不写死在内容规范中；超过预算后使用通过同一套规则验收的本地保底事件。任何阶段都不得 fail-open。

## 12. 校验矩阵与错误码

| 规则 ID | 检查内容 | 责任方 |
|---|---|---|
| `FATE_SCHEMA` | 字段、类型、长度、未知字段、枚举 | 程序 |
| `FATE_STAGE` | `chapterIndex/age` 与身份、场景一致 | 程序 |
| `FATE_SCENE` | 时间具体、地点明确、people 只含人物 | 程序 + 语义审稿 |
| `FATE_REALITY` | 物理性质、动作实施者、知识来源、现实制度 | 正则/状态规则 + 语义审稿 |
| `FATE_ENTITY` | 回应未新增关键人、物、地点或任务 | 结构化实体校验；未接入前由语义审稿兜底 |
| `FATE_STATE` | 已付款、离场、遗失、销毁等状态不被逆转 | 状态机 |
| `FATE_CHOICE` | 两边可执行、不同、可辩护且非善恶题 | 程序基础检查 + 人工/语义评审 |
| `FATE_EFFECT` | 不可避免效果、effect、poison、stats 合法 | 程序 |
| `FATE_MEMORY` | 记忆仅来自事实且稳定 | 程序 |
| `FATE_STYLE_DRIFT` | 文学化稿与底稿事实等价 | 结构化 diff + 语义复审 |
| `FATE_SAFETY` | 敏感题材与隐私边界 | 程序过滤 + 语义审稿 |

所有阻断规则必须返回 `ruleId + field + reason`。下一轮修复提示只携带已脱敏的错误，不发送密钥、账号、联系方式或支付信息。

生产级封闭世界校验必须补充结构化上下文：

```text
entityCatalog.actors[]    = id, displayName, presence, locationId, knownFacts
entityCatalog.objects[]   = id, displayName, ownerId, locationId, availability, state
entityCatalog.locations[] = id, displayName
stateFlags[]              = paid, lost, destroyed, leftScene, consumed ...
sceneDetailCatalog[]      = 文学化阶段可以安全使用的现场细节
```

模型返回的回应还应声明使用的 `actorIds/objectIds/locationId/stateTransitions`。程序只接受输入目录中的 ID。接入前，文档和日志必须把该能力标记为“语义审查”，不能标成“确定性硬校验”。

## 13. 正反例

### 13.1 合格

第 6、7 节的“纸箱上的名字”是完整合格样例：

- 中年身份与公司场景一致；
- 事实先成立，两个回应都不能撤销纸箱和名单；
- 咽下与吐出方向清楚，但没有善恶答案；
- 两边只使用现场已有的人、纸箱、标签和名单；
- 机械效果、五毒和动作有可解释联系；
- 结果停在当刻，没有跳到回家或几天后。

### 13.2 新增关键事实

输入只有医院、收费员、收据和已完成扣费。

错误：

> 他把收据塞进公文包，赶去公司处理积压工作，鞋尖又蹭到台阶水渍。

拒绝：

```text
FATE_ENTITY · swallow.result
新增公文包、公司任务和水渍事件；这些内容不在事实或快照中。
```

修复：

> 他把收据对折握在手里，退回候诊区门口；收费员已经开始叫下一号。

### 13.3 状态逆转

事实已经写明“费用已从医保账户扣除”。

错误：

> 他回到窗口重新把复诊费付了一遍。

拒绝：

```text
FATE_STATE · exhale.result
费用已支付，回应重复付款。
```

### 13.4 年龄倒退

输入为 `chapterIndex=4, age=中年`。

错误：

> 周三早自习，他坐在初二教室第三排等班主任发卷子。

拒绝：

```text
FATE_STAGE · fact
中年主角无解释地回到学生身份。
```

### 13.5 合法边界

晚年主角在家里拿出少年时期的旧信不是天然违规；只要正文说明信一直保存在抽屉、由他亲手拿出，人物没有回到过去，便可通过。

## 14. 发布验收

每次修改模型、提示词、Schema、校验器或本地事件池，必须运行同一套回归：

1. 六个人生阶段全部覆盖。
2. 六种命运轮廓全部覆盖。
3. 咽下与吐出分别覆盖全部合法 `effect`。
4. 每个错误码至少有一个坏样本和一个最小修复样本。
5. 物体拟人、年龄倒退、重复付款、新增实体、人物返场、旧物瞬移和文学化事实漂移必须全部被拒绝。
6. 合法边界样本不得被误杀。
7. 亲口回应和命运回响单独回归，不能只测普通二选一。
8. 本地保底事件必须通过与 AI 事件相同的检查。

阻断门槛：

- 最终进入游戏的命运牌，硬规则违规数必须为 0。
- 固定非法样本拒绝率必须为 100%。
- 固定合法样本接受率必须为 100%。
- 模型生成的首次通过率、重试后通过率、降级率、P50/P95、token 与单卡成本必须落盘，但性能门槛由当期模型评测报告根据预取窗口决定。
- 人工盲评至少检查：易懂、可信、本局相关、选择张力、非道德题、文风与重复度。

## 15. 落盘与追踪

每张 AI 命运牌至少记录：

```text
traceId
policyVersion / schemaVersion / promptVersion / model
快照哈希与脱敏后的局内上下文
各阶段原始产物、最终产物和字段所有者
ruleId、拒绝原因、重试次数与是否降级
各阶段延迟、tokens、费用
最终选择、命运回执与回响状态
```

玩家亲口回应属于用户输入，必须脱敏；不得记录 API Key、账号、支付标识、联系方式或其他直接个人信息。日志保留期限和查询权限由发布环境另行配置。
